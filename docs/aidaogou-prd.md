# AI 智能商城导购平台 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | AI 智能商城导购平台 |
| 文档版本 | V1.0 |
| 产品形态 | 用户商城 + 管理后台 |
| 核心能力 | AI 导购、商品问答、RAG、Function Tool、效果验收 |

## 2. 项目背景

传统商城能够展示商品，但用户仍需要自己理解参数、比较商品并判断是否适合自己。商品资料又分散在详情、参数、售后和运营文档中，直接交给大模型容易出现知识过期、回答无依据和动态价格库存不准确等问题。

本项目以商品为中心建立可维护的知识与业务闭环：资料进入知识库，经切片和向量化后参与检索；AI 根据意图决定使用知识库还是调用实时工具；每次运行都可追溯并可验收。

## 3. 产品目标

1. 让用户用自然语言完成商品咨询和导购决策。
2. 让 AI 回答有明确商品依据，减少无依据生成。
3. 让价格、库存等动态信息通过工具实时查询。
4. 让管理员维护商品、知识、模型、工具和验收用例。
5. 让每次运行留下输入、输出、工具结果和执行步骤。

## 4. 用户与权限

### 用户端

- 浏览商城首页、分类、品牌、商品列表和商品详情。
- 使用 AI 导购提出预算、场景和偏好等需求。
- 在商品详情页针对当前商品提问。
- 查看 AI 返回的商品建议、依据和价格库存信息。

用户只能访问商城前台，不能访问管理后台、知识库和运营记录。

### 管理端

- 管理商品、分类、品牌、价格、库存、图片和售后规则。
- 管理 Markdown 导入、综合知识、知识切片和 Embedding 状态。
- 配置模型、Prompt、Function Tool 和业务调试入口。
- 查看导购、商品问答、评价分析、运营报告和 Agent Step。
- 创建和执行 AI 效果验收用例。

## 5. 信息架构

### 用户端

商城首页 → 分类 / 品牌筛选 → 商品列表 → 商品详情 → AI 导购 / 商品知识问答。

### 管理端

商城管理、AI 基础配置、AI 知识库、AI 导购与运营、Agent Step 执行步骤、AI 效果验收。

## 6. 核心业务流程

```text
商品资料维护 → Markdown / 商品详情导入 → 资料清洗
→ 综合知识整理 → 按规则切片 → Embedding 向量化
→ 用户提问 → 意图识别 → RAG 检索或 Function Tool 调用
→ 生成有依据的回答 → 记录 Agent Step → 效果验收与复盘
```

## 7. 功能需求

### P0 商品与知识底座

| 功能 | 需求说明 | 验收标准 |
| --- | --- | --- |
| 商品管理 | 维护名称、编号、分类、品牌、价格、库存、图片、卖点、参数和描述。 | 新增、编辑、上下架和查询可用。 |
| Markdown 导入 | 识别商品名称、品牌、分类、价格、库存、卖点、标签、参数、描述和图片地址。 | 上传后自动回填，管理员可修改后保存。 |
| 品牌同步 | 导入资料中的新品牌不存在时，支持同步创建品牌。 | 商品保存时品牌可正常关联。 |
| 知识切片 | 按商品选择切片，避免重复切分已完成资料。 | 记录商品、序号、标题、内容和状态。 |
| Embedding | 为可用切片生成向量并记录模型、状态和更新时间。 | 可检索切片有明确向量状态。 |

### P0 AI 导购与商品问答

| 功能 | 需求说明 | 验收标准 |
| --- | --- | --- |
| AI 导购 | 识别预算、场景、偏好、品类和约束条件。 | 返回商品来自商城数据，并说明匹配依据。 |
| 商品问答 | 问题必须绑定当前商品 `productId`。 | 优先引用该商品综合资料，不串商品。 |
| RAG 检索 | 根据问题召回相关商品知识切片。 | 结果包含商品和切片来源。 |
| Function Tool | 价格库存、售后等动态信息通过工具查询。 | 成功返回真实结果，失败明确提示。 |
| 范围兜底 | 对天气、量子计算等非商城问题拒答。 | 不编造商品信息，并说明服务范围。 |

### P1 管理与可观测性

| 功能 | 需求说明 | 验收标准 |
| --- | --- | --- |
| Agent Step | 记录输入、输出、工具调用、结果、下一步动作和错误。 | 可按一次运行查看完整链路。 |
| 导购记录 | 管理员查看用户导购任务和结果。 | 记录需求、推荐商品、时间和状态。 |
| 商品问答记录 | 管理员查看商品详情页问答。 | 记录 productId、问题、回答和来源。 |
| AI 效果验收 | 支持标准用例、关键词评分、人工通过和失败复盘。 | 显示总用例、通过、失败、准确率和结果。 |

## 8. AI 工作流设计

1. 接收问题并校验必要参数。
2. 判断导购、商品知识、价格库存、售后或非商城问题。
3. 商品知识问题进入 RAG 检索；价格库存问题调用 Function Tool。
4. 导购问题结合商品筛选和知识依据生成推荐。
5. 非商城问题进入范围兜底，并在执行步骤中记录原因。

### 回答约束

- 不凭空创造商品、价格、库存、功效和售后政策。
- 商品问答必须绑定 `productId`。
- 动态数据优先来自工具，不以历史切片代替实时价格库存。
- 推荐理由需要回溯到商品字段或知识切片。
- 无法检索或工具失败时说明信息不足，不伪造结论。

## 9. 数据对象

- `Product`：商品基础资料、价格、库存、分类和品牌。
- `KnowledgeDocument`：商品综合知识资料及来源。
- `KnowledgeChunk`：切片序号、标题、内容、字数和处理状态。
- `Embedding`：切片向量、模型、状态和更新时间。
- `AgentRun`：一次导购或问答运行的整体记录。
- `AgentStep`：运行中的单个步骤、输入、输出、工具和耗时。
- `AcceptanceCase`：验收维度、输入、预期、关键词、得分和状态。

## 10. 效果验收指标

以下为目标口径，用于后续持续评测，不代表所有指标已经达到生产标准。

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| RAG | 相关切片召回准确率 | ≥ 80% |
| 回答 | 商品事实一致性 | ≥ 90% |
| 导购 | 约束条件命中率 | ≥ 85% |
| 工具 | 价格库存调用成功率 | ≥ 95% |
| 兜底 | 非商城问题拒答率 | 100% |
| 可观测性 | 运行步骤完整率 | 100% |

## 11. 异常与边界

- `productId` 缺失：商品问答拒绝执行并提示必要参数。
- 商品不存在或已下架：不返回无效商品，提示重新选择。
- 知识库无命中：说明资料不足，必要时引导人工确认。
- 工具超时：返回失败提示，并在 Agent Step 中记录错误。
- 模型输出不符合格式：保留原始响应，标记失败并允许复盘。
- 重复切片：已完成切片不进入待切片队列，除非管理员明确重建。

项目已经具备商城、知识库、RAG、Function Tool、AI 导购、商品问答、执行步骤和效果验收等核心模块。后续重点是继续提升真实数据下的准确率、稳定性、可观测性和生产化能力。
